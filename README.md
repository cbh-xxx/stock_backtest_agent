# 股票回测 Agent

网页接收策略描述。程序先在 Chroma 检索本地资料，再请 DeepSeek 提取规则 JSON。校验通过后，程序从规则生成完整的 Backtrader 策略类。你可以修改规则、展开审阅实际执行的 Python，并逐次确认运行。

## Windows 启动

1. 在项目的 `.streamlit/secrets.toml` 顶层配置三项。执行器可复用现有 Python，填写它的绝对路径。TOML 单引号可以保留 Windows 路径中的反斜杠。

```toml
DEEPSEEK_API_KEY = "你的 DeepSeek 密钥"
DASHSCOPE_API_KEY = "你的百炼密钥"
BACKTEST_RUNNER_PYTHON = 'D:\Anaconda\python.exe'
```

2. 用该 Python 安装项目依赖，然后从项目目录启动网页。以下命令以现有 Anaconda Python 为例。

```powershell
& 'D:\Anaconda\python.exe' -m pip install -r requirements.txt
& 'D:\Anaconda\python.exe' -m streamlit run app.py
```

## 验收示例

在网页输入「回测 sh.600000，2024-01-01 至 2024-06-30。14 日 RSI 小于 30 时买入，用账户权益的 10%，RSI 大于 70 时卖出」。检查源码和参考来源，确认参数后运行。报告、净值图和回撤图应使用同一次运行的数据。

试着把入场阈值 30 改成 25。既可以通过对话修改，也可以编辑规则 JSON 后保存。两种操作都应生成新版本，并在「差异」中显示规则和 Python 的变化。确认表单里的标的、日期和账户参数后，点击「执行代码」。重跑时也需要再次点击。

混合条件示例：「回测 sh.600000，2024-01-01 至 2024-06-30。成交量达到前 20 日均量的 1.5 倍，且（14 日 RSI 低于 30 或 5 日均线上穿 20 日均线）时买入。每只股票用权益的 10%，较成交价下跌 5% 止损，持有满 10 个可交易日也卖出。」检查入场条件中是否保留括号，预热是否为 20 根日线。

可在 JSON 编辑框末尾添加一个额外的右括号，或删除 `entry` 后保存。页面应指出格式位置或缺失字段，原有版本应仍可查看。模型端的空白和无效 JSON 会自动重试一次。

策略由配置的 Python 在子进程中运行，仍拥有当前账户的文件和网络权限。只有你在网页确认的请求才会启动子进程。代码版本和结果只在当前会话保留。

## 追问回测结果

同一会话跑两次后，可以问「第一次回测第一笔买入的信号日、成交日和 RSI 分别是多少？」或「第二次最大回撤在哪一天？那天 sh.600000 的收盘价是多少？」。每轮聊天会附带已完成运行的结果和回测输入行情。超过上下文预算时，页面列出只保留摘要的运行，Agent 可以按运行编号和日期补查。旧版本策略运行可能没有下单指标记录，需使用新生成的代码重新回测才能采集。
