# 日线回测规则知识库

<details>
<summary>人工查阅：完整策略示例、成交过程和结果字段</summary>

### 示例一　RSI 阈值

需求：14 日 RSI 低于 30 时买入，高于 70 时卖出，单只股票目标仓位为账户权益的 10%。预热需要 14 根可交易日线。RSI 恰好为 30 时不触发买入，恰好为 70 时不触发卖出。

```json
{
  "entry": {"kind": "rsi", "period": 14, "op": "lt", "threshold": 30},
  "exit": {"kind": "rsi", "period": 14, "op": "gt", "threshold": 70},
  "position_fraction": 0.1
}
```

### 示例二　简单均线上穿和下穿

需求：5 日简单均线上穿 20 日简单均线时买入，下穿时卖出，单只股票目标仓位为 10%。预热需要 20 根可交易日线。两根均线已经连续多天保持同一相对位置时，单凭当天快线高于或低于慢线不会再触发交叉。

```json
{
  "entry": {"kind": "ma_cross", "fast": 5, "slow": 20, "direction": "up"},
  "exit": {"kind": "ma_cross", "fast": 5, "slow": 20, "direction": "down"},
  "position_fraction": 0.1
}
```

### 示例三　放量与组合入场

需求：当日成交量达到前 20 根日线均量的 1.5 倍，且 14 日 RSI 低于 30 或 5 日均线上穿 20 日均线，两组条件同时满足才买入。单只股票目标仓位为 10%。收盘价较买入成交价下跌达到 5%，或持有满 10 根可交易日线时，发出卖出信号。预热需要 20 根可交易日线。

```json
{
  "entry": {
    "kind": "all",
    "conditions": [
      {"kind": "volume_ratio", "period": 20, "op": "gte", "threshold": 1.5},
      {
        "kind": "any",
        "conditions": [
          {"kind": "rsi", "period": 14, "op": "lt", "threshold": 30},
          {"kind": "ma_cross", "fast": 5, "slow": 20, "direction": "up"}
        ]
      }
    ]
  },
  "position_fraction": 0.1,
  "stop_loss": 0.05,
  "max_hold_days": 10
}
```

### 示例四　突破后持有到期末

需求：当日收盘价严格高于前 20 根可交易日线的最高价时买入，单只股票目标仓位为 10%，持有到期末。预热需要 20 根可交易日线。期末仍持有的股票按最后可用收盘价计入账户权益。

```json
{
  "entry": {"kind": "breakout", "period": 20, "direction": "above"},
  "position_fraction": 0.1,
  "hold_to_end": true
}
```

### 修改示例　只改 RSI 买入阈值

以示例一为当前策略，用户要求「把买入阈值从 30 改成 25，其他按原策略」。只更新 `entry.threshold`，继续使用 14 日周期、严格小于的买入比较、严格大于 70 的卖出条件和 10% 仓位。修改后输出完整规则对象，预热仍为 14 根。

```json
{
  "entry": {"kind": "rsi", "period": 14, "op": "lt", "threshold": 25},
  "exit": {"kind": "rsi", "period": 14, "op": "gt", "threshold": 70},
  "position_fraction": 0.1
}
```

### 从信号到成交

1. **信号日收盘**。假设某股票当天 RSI 为 28，满足示例一的入场条件。账户权益为 100,000 元，可用现金为 6,000 元，10% 的目标仓位是 10,000 元，因此下单预算取 6,000 元。若当日收盘价为 10 元，费率为 0.001，策略用 `int(6000 / (10 * (1 + 0.001)))` 估算下单 599 股。
2. **同一标的的下一可交易日开盘**。假设该股随后停牌，复牌后才有下一根可交易日线。市价单按这根日线的开盘价模拟成交。若开盘价为 10.20 元，成交 599 股所需的成交额和费用合计超过 6,000 元，模拟账户可能因资金不足而未成交。
3. **成交后的日线**。若买单成交，持有期从买入成交日算第 1 根日线。止损和止盈用当日收盘价与买入成交价比较。满足退出条件时先发出卖出信号，再等下一根可交易日线开盘模拟成交。
4. **回测区间结束**。最后一根日线收盘发出的订单可能没有下一根日线可供成交，结果会保留为未成交。仍持有的股票按期末可用收盘价估值，计入最终账户权益。

### 区分取数失败和订单未成交

| 情况 | 含义 |
| --- | --- |
| 缺少预热行情 | 例如策略需要 20 根历史日线，但请求开始日前只有 12 根可交易日线。行情准备失败，本次回测还没有进入引擎。 |
| 订单资金不足 | 回测已经运行并产生买入信号。下单数量按信号日收盘价估算，下一可交易日开盘价上涨后，账户可能无法支付成交额和费用。查看未成交原因。 |
| 区间结束仍有活动订单 | 回测已经运行，但在结束前订单未成交。结果会记录信号及「回测区间结束，订单未成交」的原因。 |

### 怎样读回测结果

| 字段 | 记录内容 |
| --- | --- |
| `signal_date` 和 `fill_date` | 前者是策略提交订单的信号日。后者是模拟成交日，只在成交记录里存在。 |
| `signal_detail` | 下单时采集的依据。指标条件可包含规则、是否命中、当时的观测值和在条件树中的位置。止损、止盈或持有期触发时，记录对应阈值及用于判断的数值。 |
| `reason` 和 `failure_reason` | `reason` 说明为什么发出订单，例如「入场条件满足」或「止损」。`failure_reason` 说明订单为什么未成交。 |
| `shares`、`price` 和 `fee` | 实际模拟成交的股数、价格和手续费。报告里的手续费总额是各笔成交费用之和。 |
| `equity` 和 `holdings` | 前者是按日记录的账户权益。后者是回测结束时仍持有的股票及数量。 |

回测依据可参阅 [Backtrader 订单说明](https://www.backtrader.com/docu/order/) 和 [Backtrader 订单执行说明](https://www.backtrader.com/docu/order-creation-execution/order-creation-execution/)。

## 日线与预热

股票使用 BaoStock 前复权日线，字段包括日期 `date`、股票代码 `code`、开盘 `open`、最高 `high`、最低 `low`、收盘 `close`、成交量 `volume` 和交易状态 `tradestatus`。引擎使用过滤停牌后的 OHLCV 日线，日期作为索引。指数只用于基准比较，保留收盘序列。窗口和持有期按同一标的的可交易日线计数。

预热行情取自请求开始日之前，根数由程序取入场和退出指标所需周期的最大值，均线交叉用慢线周期。14 日 RSI 和 20 日慢线组合需要 20 根预热日线。预热期间不下单。策略在收盘时判断信号，独立市价单在同一标的的下一可交易日开盘模拟成交。若区间内没有机会成交，订单可留在未成交明细。

## 规则 JSON

顶层必填 `entry` 和 `position_fraction`，分别表示入场条件和单只股票目标仓位比例。仓位比例大于 0 且不超过 1。可选字段为 `exit`、`stop_loss`、`take_profit`、`max_hold_days` 和 `hold_to_end`。止损比例大于 0 且小于 1，止盈比例大于 0，最长持有期是至少为 1 的整数。`hold_to_end` 是布尔值，默认 `false`。无退出条件时，用户须明确选择持有到期末。

`entry` 和 `exit` 通过 `kind` 区分 `rsi`、`ma_cross`、`volume_ratio`、`breakout`、`all` 和 `any`。周期用整数，阈值和比例用数值，例如 `0.1` 表示 10%。带引号的 `"0.1"` 是字符串，会被数值字段拒绝。重复键、未知字段、`NaN` 和 `Infinity` 会报错。股票、指数基准、日期、初始资金和费率由回测运行参数提供。

## RSI

`kind: "rsi"` 使用 `period`、`op`、`threshold`。周期是 2 到 2520 的整数，阈值在 0 到 100 之间，含两个端点。项目对每只股票的收盘价使用 `RSI_Safe`，用当前日线的 RSI 与阈值直接比较。

14 日 RSI 低于 30 写作 `{"kind":"rsi","period":14,"op":"lt","threshold":30}`。`lt`、`lte`、`gt`、`gte` 分别是小于、小于等于、大于、大于等于。RSI 恰为 30 时，`lt 30` 为假，`lte 30` 为真。要求「RSI 向上穿越某个阈值」涉及前后两根日线的比较，当前 RSI 条件只判断当日的水平。

## 均线交叉

`kind: "ma_cross"` 使用 `fast`、`slow`、`direction`。周期是 1 到 2520 的整数，且 `slow > fast`。均线是收盘价的简单移动平均。当前均线含当日收盘，前一根的均线窗口截至前一根可交易日线。

`up` 要求前一根快线小于或等于慢线，且当前快线严格大于慢线。`down` 要求前一根快线大于或等于慢线，且当前快线严格小于慢线。5 日线上穿 20 日线写作 `{"kind":"ma_cross","fast":5,"slow":20,"direction":"up"}`。两线前一根相等、当前快线在上方，算上穿。当前相等或两根日线的快线都在上方，均不算上穿。当前规则支持简单均线交叉，单独的「快线在慢线上方」或指数移动平均线交叉无法用这个条件表达。

## 成交量倍数

`kind: "volume_ratio"` 使用 `period`、`op`、`threshold`。周期是 1 到 2520 的整数，阈值是非负数。以当日成交量除以前 `period` 根可交易日线的平均成交量，历史窗口排除当天。历史均量为零时，条件直接判为未命中。

「达到前 20 日均量的 1.5 倍」写作 `{"kind":"volume_ratio","period":20,"op":"gte","threshold":1.5}`。当日量为 150、历史均量为 100 时，倍数恰为 1.5，满足 `gte`，不满足 `gt`。「放量买入」如果没有给出周期、倍数或明确的比较条件，应请用户补充。

## 价格突破

`kind: "breakout"` 使用 `period` 和 `direction`。周期是 1 到 2520 的整数。`above` 要求当日收盘价严格高于此前窗口内各日 `high` 的最大值。`below` 要求当日收盘价严格低于此前窗口内各日 `low` 的最小值。历史窗口排除当天。

收盘突破前 20 根日线最高价写作 `{"kind":"breakout","period":20,"direction":"above"}`。若历史最高价为 12 元，当日收盘为 12 元不触发，收于 12.01 元才触发。盘中最高价触及该边界的需求需要另行说明，当前条件按收盘判断。

## 条件组合

`all` 和 `any` 均使用非空的 `conditions` 数组。前者要求所有子条件成立，后者要求至少一条成立。子节点可以是另一组条件。买卖条件合计最多 64 个节点，每棵条件树从根算起最多 6 层，分组本身也计入节点数。

「A 且（B 或 C）」写成 `all` 组，里面放 A 和包含 B、C 的 `any` 组。例如「放量且（RSI 低于 30 或均线上穿）」可写成 `{"kind":"all","conditions":[{"kind":"volume_ratio","period":20,"op":"gte","threshold":1.5},{"kind":"any","conditions":[{"kind":"rsi","period":14,"op":"lt","threshold":30},{"kind":"ma_cross","fast":5,"slow":20,"direction":"up"}]}]}`。即使 B 和 C 同时满足，只要 A 不成立，整组就不成立。

## 仓位

`position_fraction` 是单只股票目标建仓金额占账户权益的比例，取值大于 0 且不超过 1。买入预算取「账户权益乘以比例」和「可用现金」两者中的较小值。下单股数按 `int(预算 / (信号日收盘价 * (1 + 费率)))` 估算，结果大于零时才下单。

例如权益 100,000 元、比例 0.1、可用现金 6,000 元时，目标金额为 10,000 元，实际预算取 6,000 元。股数按信号日收盘估算，模拟成交以同一标的下一可交易日的开盘为准。价格变动可能导致成交额偏离目标或订单因资金不足而未成交。

## 退出与持有到期末

`exit` 可放指标条件或条件组。`stop_loss` 和 `take_profit` 分别用大于 0 且小于 1 的止损比例，以及大于 0 的止盈比例。程序以当日收盘价除以实际买入成交价再减 1，比较跌幅或涨幅。`stop_loss: 0.05` 表示跌幅达到 5% 时发出卖出信号。`max_hold_days` 是正整数，从买入成交日计第 1 根可交易日线。

这些退出规则任一满足即发出卖出信号。同一根日线命中多项时，按止损、止盈、最长持有期、指标退出的顺序记录第一个原因。用户明确要求持有到期末时，设 `hold_to_end: true` 并省略其他退出条件。期末持仓按最后可用收盘价计入账户权益。

## 缺项与不支持的规则

交易规则有缺项时，应指出需要补充的字段。比如用户说「按 20 日均量放量买入」，仍须问达到多少倍。缺项可写成 `{"issues":[{"field":"entry.threshold","message":"请提供相对于前 20 根日线均量的放量倍数。"}]}`。`field` 指出规则字段路径，`message` 说明缺什么或当前无法表达什么。

当前支持 RSI 阈值、简单均线交叉、成交量倍数、收盘价突破和条件分组。MACD、盘中止损，以及「价格止损与某指标同时满足才卖出」超出现有规则。价格止损是独立退出项，指标条件组无法把它合并进去。遇到这些要求时，用 `issues` 标出对应字段并解释限制，保留用户原来的交易意图。
